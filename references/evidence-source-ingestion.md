# Source research, article and video ingestion, and evidence integrity

Operational guide and topic inventory. Procedures and checks are an original synthesis; use the source register for the authority, inspected portion, and limits of specific references.

### Coverage

| Area | Details to consider |
| --- | --- |
| Source classes | Normative requirement; informative guidance; original research; research synthesis; practitioner heuristic; product convention; opinion; example. |
| Research origins | Author; publisher; original experiment; sample; task; design; measures; effect; uncertainty; replication; limitations; applicability. |
| Article inspection | Full body/abstract/excerpt; publication and update dates; author; conflicts; source references; changed content; access limits. |
| Video inspection | Official page; playback; transcript; captions; timestamps; slide deck; summary; automated transcript errors; missing visuals; media permissions. |
| Current facts | Platform version; library behavior; standards status; legal applicability; jurisdiction; policy; vendor updates; source date. |
| Claim records | Claim; evidence type; source; inspected portion; inference; confidence rationale; context; limitation; owner; recheck trigger. |
| Knowledge operations | Deduplication; taxonomy; contradictions; retired guidance; licensing; paraphrase; quotation limits; link checks; reproducibility. |
| Coverage status | Operational guidance; indexed topic; partial evidence; blocked source; task-specific retrieval needed; specialist validation; unsupported. |

### Procedure

1. Start with the design decision and the type of authority needed. Prefer the original source for a technical or empirical claim.
2. Search across standards, platform/system documentation, original studies, method owners, and relevant official learning resources.
3. Inspect the material actually available. Record whether access was to full text, selected excerpts, an abstract, a transcript, or only a summary.
4. Extract the specific claim, context, applicability, uncertainty, and limitation. Keep observation separate from the interpretation added by the designer.
5. For research, examine task, population, method, measures, and conflicting findings before applying an effect as guidance.
6. For videos, use official transcripts or authorized playback when available; cite timestamps only when actually verified. Do not infer unseen demonstrations from a title.
7. Classify sources and resolve conflicts explicitly. Never promote a draft, heuristic, old convention, or inaccessible pointer into a verified current standard.
8. Write an original, concise synthesis with attribution and reuse limits. Record remaining gaps and retrieve task-specific information when needed.

### Outputs

Search and source register; evidence cards; claim-to-source map; inspected-status record; contradiction/gap log; original synthesis.

### Quality checks

Every important claim has an appropriate source and scope; current guidance is verified when material; video review status is accurate; original and interpretive claims are distinguished; inaccessible material is not treated as read.

### Limits and common failures

A search result is discovery evidence, not full-text review. An abstract cannot support details absent from it. An official video summary is not a watched video. A practitioner law catalog does not establish that every named principle is a universal empirical law. This corpus is broad and expandable; do not claim to contain every UX publication, every niche rule, or all knowledge.

#### Evidence card

| Field | Required content |
| --- | --- |
| Decision | The practical question the evidence informs |
| Claim | A specific, testable or attributable statement |
| Source | Author/authority, title, link, publication/update date |
| Inspected | Full text, excerpt, abstract, transcript excerpt, summary, playback, or inaccessible pointer |
| Context | Population, task, platform/version, environment, domain, jurisdiction as relevant |
| Finding | What the source actually supports |
| Interpretation | The additional design implication, explicitly marked as inference |
| Limits | Missing detail, alternative explanations, conflicting evidence, scope |
| Action | Apply, adapt, test, retrieve more evidence, seek specialist review, or defer |
| Maintenance | Owner and re-verification trigger |

#### Breadth with integrity

Use the topic inventory to prevent accidental omissions. Use the evidence register to prevent false certainty. Coverage is not proof of expertise; a listed method or niche can still need original-source reading, organizational rules, or field validation for the actual task.

Classify a design recommendation's basis in prose when useful: applicable requirement; established platform convention; evidence-supported finding; contextual heuristic; project decision; or provisional assumption.
